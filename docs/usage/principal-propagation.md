# Principal propagation

OnPremise HTTP destinations support `Authentication: PrincipalPropagation`, a Cloud Connector virtual URL and `CloudConnectorLocationId`, without User/Password. Forward the logged-in XSUAA token as `Authorization: Bearer ...`, including from MCP clients. Missing tokens return 401 `SAP_USER_TOKEN_REQUIRED`.

The SAP Cloud SDK receives the user JWT in destination fetch options (`jwt`) on all requests, including CSRF and retries, and supplies connectivity proxy authentication. Startup loads tools without logging on to SAP; authentication happens per request.

For authentication PP ignores `x-sap-login` and `x-sap-password`: the user's JWT always authenticates the request. Basic overrides remain available for non-PP destinations. `x-sap-client` remains optional.

For every system type, an explicit `x-sap-responsible` wins, followed by the logged-on SAP user from `/sap/bc/adt/core/http/systeminformation`, then uppercased `x-sap-login` if the endpoint has no user or is unavailable. The endpoint exists on ABAP Cloud and newer on-premise releases. Under principal propagation, `x-sap-login` is only a responsible hint, never an authentication credential. With no user, creates are refused with `system_context_missing`; send `x-sap-responsible` with an SAP user ID. Resolution runs once per authenticated session after connector creation, using the connected SAP session. A bounded cache reuses the user and system across requests; missing endpoints are cached and transient failures are retried. Cloud retains lib's default resolution and retryable failure behavior. Dump scope still uses the authenticated CAP user and effective authentication mode.

System information (logged-on SAP user as responsible, system ID as master system) is resolved once per authenticated session, after connecting on the first SAP request, using that same connection. The process-local LRU cache holds up to 1000 identities, including unavailable endpoints. Keys include destination (or direct URL), SAP client, and authenticated principal: JWT user and tenant/origin for principal propagation, uppercase basic login, or the technical destination identity. Tokens are never retained in keys. PP entries expire at JWT `exp`; other entries default to eight hours (`SYSTEM_IDENTITY_CACHE_TTL_MS` overrides this). Transient failures are retried on the next connector creation. Control requests do not query SAP. Explicit `x-sap-responsible` still wins; `x-sap-login` remains the fallback. Cloud identity behavior is unchanged.

In the chat WebUI, selecting a destination with `requiresCredentials: false` hides SAP Login and SAP Password and shows a single sign-on note. SAP Client remains optional. Connect uses the platform session without saving SAP credentials or sending `x-sap-login` / `x-sap-password`. The active destination probe also resolves and connects with the forwarded user JWT, preserving principal propagation and the selected client. Missing destination metadata keeps the SAP credential prompt. If the platform token is missing (`401 SAP_USER_TOKEN_REQUIRED`), reload and sign in again; the UI does not ask for SAP credentials.
