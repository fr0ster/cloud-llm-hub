# Facet spike — several records per tool, collapsed to tools

TL;DR: **Faceting helps a little, without a reranker, but it does not reach R3c at the same tool count.**
- Best faceted config: hybrid, C1 max, N=15, V3 (full+operation) or V1d (full + deterministic op/object).
  - At k2=5 it gets EN-ext required-recall 0.966 with 8.3 tools. R0 gets 0.943 with 8.3 tools; R3c gets 0.977 with 9.4.
  - At k2=8, V1 C1 gets 0.977 with 12.8 tools, the same recall as production K15 (25 tools).
- The gain is 2 rows out of 87, and 1 row is worth 0.011. That is within noise-level evidence.
- Single-step queries rise to 1.000, but multi-step queries do not move (0.714 → 0.786).
- Non-ASCII queries do not improve.
- Count-based collapse (C2) and sum/RRF collapse (C3) are **worse** than max (C1). The facet-only variant V2 (no full doc) is clearly worse.
- Putting faceted stage 1 in front of Cohere (Vx+R3c) changes nothing: R0's top-30 already contains the needed tools.
- One combination does work. **R3c ∪ faceted top-3** fixes the one R3c break (BAPI where-used) and reaches 1.000 / 10.7 tools.
  At k2=3 it reaches 0.977 with 7.6 tools, against R3c's 9.4. This variant was picked after looking at the data.

## Setup (identical to ../spike-rerank)
- Inputs reused from the reranker spike: corpus.json (237 tools), queries, labels, tokenizer, BM25, metrics, sets, and per-collection top-K concatenation (reader + writer).
  Structural rows are excluded.
- Embedding vectors were read from that spike's cache, read-only. 802 new facet vectors and 37 clause vectors went to our own cache.
- Cohere scores were also read from that spike's cache. All (query or clause, tool) pairs were already scored, so this spike made **0 new rerank calls**.
- Baselines reproduce exactly:
  - R0 hybrid K5: 0.943 / .225 / 8.3; K15: 0.977 / 25.
  - R3c hybrid k5: 0.977 / .234 / 9.4.
  - Cosine: R0 K5 0.885; R3c 0.954.
- Records per tool:
  - `full`: the production doc.
  - `operation` and `object`: generated by AI Core gpt-4o-mini at temperature 0, from name, description, parameter names and intents only.
    The prompt has one neutral few-shot example (CreateDomain) and no hard-query wording. Cache: facets-llm.jsonl.
  - Deterministic alternative `opDet` / `objDet` (V1d):
    - opDet = name verb + noun + the description's first clause;
    - objDet = the name noun.
- Search: one query embedding, scored against all records of a collection. Hybrid = 0.7·cos + 0.3·BM25/max, with BM25 over the record texts. Then top-N records → collapse → top-k2 tools per collection.
- Collapse methods:
  - C1 = max;
  - C2 = count of records in top-N, ties broken by max;
  - C3rrf = Σ 1/(60+rank);
  - C3sum = Σ score.

## Recommendation
1. **Does faceting beat R0 without a reranker?** Marginally.
   - Hybrid V3 (full+operation) or V1d with **C1 max**: +0.023 required-recall at k2=5, with the same 8.3 tools and no breaks.
   - At k2=8 V1 or V1d reaches production-K15 recall (0.977) with ~13 tools instead of 25. That saves ~12 tools, or ≈3k prompt tokens, with no extra latency or service.
   - Use C1. Count-based and RRF collapse are consistently worse.
   - Never drop the full doc (V2).
2. **Does it approach R3c?** On single-step queries, yes (1.000 vs 0.973). On multi-step and non-ASCII queries it does not (0.786 vs 1.000; 0.73 vs 0.96). R3c remains the better stage 2.
3. **Combine with R3c?** Not as a stage 1 in front of Cohere: there is no gain. Use it as a **union**: R3c top-k plus faceted C1 top-3.
   This is the only config at 1.000 (k5, 10.7 tools), and it fixes the BAPI where-used break.
   It was chosen after looking at the data on 87 rows, so validate it on fresh queries before adopting it.
4. If faceting is adopted, prefer the **deterministic V1d facets**. They have no LLM step and equal V3 on EN-ext, but they are slightly worse on non-ASCII.
   Re-check this after any lib description change.
