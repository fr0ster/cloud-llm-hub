description: 'Performance-category review rules: SELECT * without a specific field list on a wide table (MEDIUM unless table is known-small); SELECT inside LOOP, especially LOOP AT itab + nested SELECT (HIGH); nested LOOP AT itab without BINARY SEARCH or hashed table when both itabs grow (HIGH); missing WHERE clause on SELECT against a large transactional table (HIGH); SELECT SINGLE without all key fields specified (MEDIUM — ambiguous result); READ TABLE without BINARY SEARCH on a sorted/standard table that grows (MEDIUM); repeated calls to the same DB / function inside a loop where memoization would work (HIGH/MEDIUM depending on call cost); FOR ALL ENTRIES without an IS NOT INITIAL guard on the driver table (HIGH — empty driver = full table read); DELETE / MODIFY / INSERT inside LOOP without batching (MEDIUM); string building by repeated CONCATENATE inside a loop (LOW — perf-relevant only at high iterations). If the issue is purely about scaling, it belongs here; if a modern-ABAP idiom both fixes a perf issue AND improves readability, it can also appear in maintainability.'
